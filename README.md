# stream-loader

Консольное приложение на Go для автоматической записи Twitch-стримов. Оно не использует базу данных, Twitch API или HTTP-сервер: Streamlink получает поток, а FFmpeg сохраняет его локально отдельными TS-чанками.

```text
config.json
  ↓
monitor (отдельная goroutine на канал)
  ↓
streamlink status check
  ↓
streamlink --stdout
  ↓ pipe
ffmpeg segment muxer
  ↓
recordings/<channel>/<start-time>/00001.ts
```

## Требования

- Docker;
- Docker Compose.

Go, Streamlink и FFmpeg устанавливать на хост не нужно. Multi-stage Docker-сборка компилирует Go-приложение и включает Streamlink и FFmpeg в runtime-образ. В Dockerfile закреплены Go 1.27.0, Python 3.14.7, Streamlink 8.6.0 и FFmpeg 7.1.5.

## Конфигурация

Если `config.json` ещё нет, скопируйте пример и отредактируйте список каналов:

```bash
test -f config.json || cp config.example.json config.json
test -f .env || cp .env.example .env
```

```json
{
  "channels": [
    {
      "name": "shroud",
      "max_recording_minutes": 180,
      "quality": "best"
    },
    {
      "name": "xqc",
      "max_recording_minutes": 60,
      "quality": "720"
    }
  ],
  "output_dir": "./recordings",
  "check_interval_seconds": 30,
  "chunk_duration_minutes": 5
}
```

`max_recording_minutes` задаётся отдельно для каждого канала:

- значение больше нуля останавливает запись через указанное число минут;
- `0` снимает ограничение и записывает до завершения стрима.

`quality` также задаётся отдельно для каждого канала и принимает только строковые значения:

- `"best"` — максимальное доступное качество;
- `"1080"` — лучшее доступное качество не выше 1080p60;
- `"720"` — лучшее доступное качество не выше 720p60.

Если `quality` отсутствует или содержит пустую строку, используется `"best"`. Если Twitch вообще не предлагает поток в заданном диапазоне, Streamlink использует максимальное доступное качество как fallback. FFmpeg не масштабирует и не перекодирует видео, поэтому качество выбирается только из вариантов, предоставленных Twitch.

После достижения лимита приложение не начнёт повторную запись того же стрима. Новая запись разрешается только после подтверждённого перехода `online → offline → online`. Это состояние хранится в памяти и сбрасывается при перезапуске приложения.

Относительный `output_dir` вычисляется от рабочей директории, из которой запущена команда.

## Запуск

Запускайте из корня репозитория:

```bash
test -f config.json || cp config.example.json config.json
test -f .env || cp .env.example .env
mkdir -p recordings logs
docker compose up --build
```

Compose монтирует:

- `./config.json` в `/app/config.json` только для чтения;
- `./recordings` в `/app/recordings` для записи TS-чанков;
- `./logs` в `/app/logs` для файловых логов.

Значение `"output_dir": "./recordings"` из примера конфига менять не нужно: рабочая директория контейнера — `/app`.

Для фонового запуска и просмотра логов:

```bash
docker compose up --build -d
docker compose logs -f streamrec
```

Остановка:

```bash
docker compose down
```

Compose отправляет `SIGTERM`, после чего Go-приложение отменяет корневой context и останавливает дочерние процессы Streamlink/FFmpeg. Grace period перед принудительной остановкой контейнера составляет 15 секунд.

При старте приложение по-прежнему проверяет наличие Streamlink и FFmpeg внутри образа. Если конфиг отсутствует или некорректен, контейнер завершится с понятной ошибкой.

## Логи

Логи одновременно выводятся в консоль и записываются в `./logs/log.json`. В консоли используется читаемый текстовый формат, а файл содержит JSON Lines: одна JSON-запись на строку.

При старте приложение выводит загруженные настройки, включая каналы, качество, лимиты записи, интервалы, директорию записей, путь к логам и срок их хранения. На каждой проверке канала пишутся события `Проверяем online`, `<account> не онлайн` или `Идет запись`.

Срок хранения архивных логов настраивается в `.env`:

```dotenv
LOG_RETENTION_DAYS=7
```

Значение должно быть целым числом больше нуля. По умолчанию архивы хранятся 7 дней. Ротация выполняется ежедневно по UTC: завершённый `log.json` переименовывается в `log-YYYY-MM-DD.json`. Если архив с таким именем уже существует, новый получает суффикс `-2`, `-3` и так далее. Просроченные архивы удаляются при старте приложения и после каждой ротации.

## Записи

Результат сохраняется так:

```text
recordings/
  shroud/
    2026-09-14_20-30-00/
      00001.ts
      00002.ts
      00003.ts
```

FFmpeg работает в режиме stream copy и не перекодирует видео. Segment muxer разрезает поток приблизительно по `chunk_duration_minutes`; фактическая граница зависит от ближайшего ключевого кадра. При аварии уже завершённые TS-чанки не перезаписываются, а потерян может быть текущий незавершённый чанк. Автоматическое объединение файлов не выполняется.

Если recorder неожиданно завершился, приложение через 5 секунд снова проверяет канал и повторяет запись в ту же директорию. Нумерация продолжается после последнего существующего чанка, а общий лимит считается от первой попытки текущей stream session.
